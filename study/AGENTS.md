# Study (server)

- Studio (`study/`) retains ID-keyed progress when an imported revision replaces its day rows; `readIndex` computes G numbers and the effective mix, and full day bodies load separately. Every plan ID and reference uses the v1 safe-ID pattern in `plan.ts`, so composite keys cannot collide and plan IDs can name state files safely. Its recursive inbox watcher closes before the module database.
- Study tags completed Pomodoro focuses `study/<planId>/<dayId>` through `pomodoro.startTagged`, never an input on `pomodoro.start`: the palette runs an input-less action at once, and an optional field turned "Avvia Pomodoro" into a form (`router-registry.test.ts` pins `start` without a schema); `core/focus-history.ts` exposes totals and completion notifications without giving modules the core database. `state.ts` exports completed minutes per day. Study material reads resolve real paths inside configured folders; `GET /files/:id?inline=1` is inline only for PDFs.
- Studio has several active plans at once (plan 40, decision 15): `activeHeaders` lists them, subjects are keyed `<plan>:<subject>` (states, shares) and days `<plan>/<day>` (`daysById` takes these keys), because two plans may share ids such as `C01`. The mix and weekly hours live in the `preferences` row `*`, not per plan; a stored mix that misses an active subject is set aside for equal shares rather than hiding that subject's days. `savePlan` never deactivates other plans; `setPlan` pauses or resumes one.
- Study error log (`errors.ts`): entries are `progress` rows of kind `error` (id uuid, JSON value), keyed by plan like every other progress record, so no migration and the `removed` list of the state file ignores them; `study.review` computes Ripasso (red and yellow threads, half-done days) server-side and parses every active day per request (shortcut, fine for hundreds of days). `server.test.ts` checks the module registry actions, labels and schemas, including `setError`; core router counts exclude Study.
- Palette records (step 64): `study.searchRecords({ query })` (`loopbackProcedure`) matches day titles from `readIndex` (`searchDays` in `read.ts`, case and accent insensitive through `core/fold.ts`, paused subjects' days included with `g: null`), cut to 3 with the full `total`, plus `headers` so the web names each subject in the same request. No day body is read. Open days have no date of their own, so the palette's detail ends with the state (Da fare, Fatta), not a day.

# Study (web)

- Studio owns the `studio` zone and adds its sections through `ui.tsx`; `use-study.ts` uses the shared module WebSocket and scoped TanStack options. Piano loads day bodies only for open groups. Piano and Piani follow the Studio mockup (plan 40): day rows and week groups are disclosure buttons with `aria-expanded` (not `<details>`), subject shades come from `subjectShade` in `use-study.ts` (foreground opacities, never `surface-raised`, which is dark in paper). The Hairline `ButtonGroup` drew no selected fill in a small filter row (the active label went dark on dark), so filters are plain pressed-state pills in a `fieldset`. With several active plans (decision 15) `studySubjects` labels each subject by its plan (`<plan>:<subject>` keys), Piano groups by week instead of phase and opens the first group when the current day is filtered out. Tailwind `max-w-md` resolves to this project’s 1rem spacing token, so use named width tokens such as `max-w-dialog-md` for forms.
- `day-body.tsx` is shared by Piano and Oggi; only Oggi passes a tick handler. Oggi's note and step drafts retain failed edits across tab navigation, and the index supplies the selected current day across all active plans.
- Study's instrument Pomodoro passes the current day tag on start (`pomodoro.startTagged`) and shows the day's minutes in its footer; Piano rows show studied minutes only above zero, beside the planned estimate. Oggi polls `focusMinutes` every 3 s (a `shortcut:` comment), Piano reads it on mount; `material.tsx` opens an authenticated PDF as a blob in a synchronously opened tab so paired devices can display it at `#page=N`. Library downloads use the attachment route.
- Studio Ripasso (`review.tsx`) and the inline error form (`error-form.tsx`, shared by Oggi and Ripasso): the form lives in the panel, no dialog. Rows are dashed-separated, filters are `aria-pressed` pills like Piano. Visual baselines seed their data in `study.visual.spec.ts` (`seedReview`, undone in `finally`) so the other Studio baselines keep their single-step days.
- Study `day-body.tsx` (Oggi and Piano): Oggi numbers steps and highlights the first open step with a named error button; the other error buttons remain available on hover and keyboard focus. Never put a path or any unbreakable string in a `flex` row without `min-w-0`: it pushed the `ml-auto` button over the next column (step 43b). "Da aprire" = day `materials` then step files, deduplicated by path. `RegistryButton` `name` is the accessible name when it must say more than the label; `TextMorph` duplicates button text, so e2e reads `aria-label`, not `toHaveText`. `StepFile` is exported for reuse by the Panoramica widget.
- Studio Panoramica widget (`widget.tsx`, `small`/`medium`/`large`, registered in `ui.tsx`): shares `useCurrentStudyDay`, `useStudySteps`, and the module-level `stepDrafts` store in `use-study.ts` with `StudyToday` (`openToday` stays on the Studio page only). `useStudySteps` updates `draft.values` and `draft.failed` immutably so React Compiler memoization sees failures across hook callers; `widget.tsx` reads `trpc.modules.enabled` directly instead of `lib/enabled-modules.ts` to avoid a module import cycle (`modules.ts` -> `widget.tsx` -> `enabled-modules.ts` -> `modules.ts`). `study-widget.spec.ts` cleans `progress` and `preferences` for `'example'` in `study.db` after each test so shard ordering with `study.spec.ts` stays independent.

- `ui.tsx` supplies the Studio zone, day line, calendar/today/record contributions and widgets. Core Pomodoro stays shared; tests use `test-server.ts` and the isolated `e2e/root/study` wrapper. The installed copy must retain its two-level relative imports; do not symlink it to the catalog checkout.

- `today-note-draft.ts` tracks the last observed server text separately from saved local text: a new query snapshot updates clean drafts only, preserving dirty, failed and pending edits. An unchanged old snapshot must not undo a successful save before its refetch arrives. Notes refetch on Oggi mount; there is no live progress subscription.
