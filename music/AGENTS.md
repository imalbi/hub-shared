# Music (server)

- Music is a catalog module. `test-server.ts` injects the module definition and scoped routes into the core test server with fake YouTube/mpv dependencies. `package.json` and the module lockfile own `youtubei.js`.
- Music follows mpv's `start-file` and keeps one upcoming song in its playlist; the IPC fake must emit playlist events for skip to update the queue. `followStart` ignores the start-file of mpv's current index (`currentPos`): a playlist can hold one song twice in a row, so matching the next song by URL alone advanced the queue on the first copy's own start (23f). YouTube calls that a mutation awaits go through a wrapper that answers 503 with a fixed message (`publicList`), never the library's text.
- Music volume is mpv's own `volume` property: `music.setVolume` (zod int 0..100, `schedule`d, 503 on IPC failure) sets it, `music.state` reports `volume` (null when mpv is unreachable). mpv allows up to 130 (`--volume-max`) but Hub's slider is 0..100. The system volume stays in the `audio` module. Fakes (`test-wiring.ts`, `e2e/root/music/server.ts`) keep a volume; the private fake owns its state.
- `music.suggestions` computes Riascolta and Radio da purely from local `favorites` and `history` (`suggestions.ts`; returns empty lists when `history` is empty), resolves Simili a via `youtube.ts` (`searchArtists` + `mapRelated`, tested against `fixtures/artist.json`), caches related artists in-memory per normalized artist for 6 hours (capped at 50 entries, errors uncached and yielding `similar: null`), and proxies all covers.
- `GET /m/music/cover/:id` (`cover-route.ts`, mounted by the module routes hook) serves binary covers (latest stored `history.cover` at `w226-h226`, fallback `mqdefault.jpg`) from the shared `covers` binary cache (`CoverImage`) with `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Sec-Fetch-Site: cross-site` refusal, and loopback/device auth; when `music` is off it answers 404.

# Music (web)

- Media music uses `favorite.tsx` for the current song and list rows; its three-view `ButtonGroup` in `search.tsx` is the extension point for playlists.
- Musica page (step 48, `page.tsx`): one fill surface, library column (`w-library-col`) and one content view split by a dashed line, no inner panel (zone-pages exempts Media from the panel count). View state is local (`library`, `playlistId`, `artistId`, `query`); a library entry clears search and artist. `SongRow` plays through a stretched title button (`after:inset-0`), everything else on the row sits at `z-10`. Shared pieces live in `parts.tsx` (no imports of other music files, to avoid import cycles with `songs.tsx` and `add-to-playlist.tsx`). Tailwind v4 adds `content` to `after:` itself: the token guard rejects `after:content-['']` and `aria-[...]` variants, use a conditional class.
- `SavedSongs` (Preferiti and Cronologia in `page.tsx`) passes `/m/music/cover/:id` to `CoverTile` (`lazy`), keeping `music.favorites` and `music.history` JSON lightweight and falling back to the note icon when a lazy cover 404s; the generic `/m` proxy handles development and preview.
- Ascolta (`listen.tsx`, step 79): renders `"Per te"` from `music.suggestions` above recent songs with three 6-column `ListenTile` rows (`Riascolta`, `Radio da`, `Simili a`), omitting any empty row and hiding the section when history is empty; `Listen` owns the pane's single `overflow-y-auto` scroller above `pb-2xl`.

- `ui.tsx` contributes the Media fill tab, floating player and large-widget `mediaUpcoming` content; core Media supplies its fallback when no module contributes a tab. `e2e/root/music` owns all Music IPC/YouTube/artwork fixtures, with no live network or desktop commands.

- `server.test.ts` preserves registry metadata/schema coverage for all Music mutations and rejects playlist deletion without explicit confirmation. Core router counts exclude Music.
